## 2. Confirmed findings (14)

Ranked by severity. Each was either verified by 3 independent adversarial lenses (reproduce / reachability / precedent) or, for the 4 marked **[manual]**, re-verified directly by reading the code myself after the workflow's individual-verification pass for that finding failed on the spend cap.

### HIGH

1. **`services/ws1-collectors/collectors/syslog_udp_server.py:322`** — Datagrams that decode/rstrip to an empty line `return` before the token-bucket check *and* before any counter update (`events_produced`/`dropped`/`shed`/`spooled`/`lost`). A flood of trivial 0-byte or CRLF-only UDP packets to the unauthenticated `:5514` listener costs a real `recvfrom` + queue + worker-thread cycle each, competes for the same bounded queue and worker pool real syslog uses, and is **invisible in every counter** — directly contradicting `test_syslog_udp.py`'s own stated invariant that every datagram is accounted for.

2. **`services/ws1-collectors/collectors/syslog_udp_server.py:339`** — The "per-tenant" token bucket is keyed on `meta["tenant_id"]`, which on a single-tenant deployment (the default: one process-level `TENANT_ID` env var) is the **same value for every external sender**. The F4 docstring's claim ("one tenant's flood cannot consume another tenant's share") and its own test only validate isolation by manually flipping the env var mid-test — a scenario that never happens on a real multi-source network edge. A flooding host can rate-limit away a concurrent real attacker's events on the same collector.

3. **`services/ws2-normalization/parsers/timeutil.py:43`** — `to_epoch_ms()` raises an uncaught `OverflowError`/`ValueError` on a JSON `Infinity`/`NaN` timestamp, contradicting its own docstring's "never raises" promise. Verified by direct execution. Python's `json.loads` accepts bare `Infinity`/`NaN` literals by default, so a crafted raw event (`{"TimeCreated": Infinity, ...}`) reaches this from every parser that calls `to_epoch_ms(meta.get("received_at"))` without a finite-check. `main.py`'s blanket `except Exception` stops the service from crashing, but the event is dead-lettered outright — the intended `to_epoch_ms(value) or fallback` fail-open never runs because the exception fires before the `or`.

4. **`services/ws2-normalization/parsers/base.py:104`** — Same root cause, different call site: `status_from_outcome()`'s `n = int(val)` has no guard, reachable from attacker-controlled CloudTrail (`responseElements.ConsoleLogin`) and k8s-audit (`responseStatus.code`) fields. A crafted `Infinity` in either field dead-letters the event — including the exact "root console login without MFA" and "privileged container creation" scenarios `contracts/rules/cloud_root_console_login.yml` and `dc_privileged_container.yml` exist to catch.

5. **`services/ws2-normalization/parsers/__init__.py:172`** — `resolve()`'s text-sniff checks `"%ASA-" in raw or "%ASA" in raw` (unanchored substring) **before** the `sshd[` check. An SSH brute-force attempt using a username containing `%ASA` (e.g. `root%ASA`) gets routed to `CiscoAsaParser`, which requires the strict `%ASA-<n>-<n>:` tag and returns `None` — the login attempt is dead-lettered instead of scored, and `common_bruteforce.yml` never sees it.

6. **`services/ws3-indexer/router.py:36`** — `_date_suffix()` can raise `OSError` (out-of-range epoch) or `TypeError` (non-numeric `time`), but every caller in `main.py` only catches `ValueError`. In the batch path (`run()`, used by `integration_e2e.py`, `demo_e2e.py`, and the contract suite) an unhandled exception aborts the **entire multi-topic batch drain** — every subsequent legitimate event/alert in that batch is silently never indexed.

7. **`services/ws3-indexer/storage/memory.py:62`** — `MemoryStore` is the **default** storage backend. Its read paths (`find_alert`, `list_alerts`, `list_events`, `count`, `indices`, `get`) iterate `self._indices` without the lock that `index()`/`index_cas()` hold. A concurrent write adding a new index key or doc during a triage-API read raises `RuntimeError: dictionary changed size during iteration` — a real crash under FENGARDE's actual concurrency model (one bus-consumer thread per topic + the triage HTTP server + the webhook thread, all sharing one `MemoryStore`).

8. **`services/ws4-detection/engine.py:475`** — `Rule._bucketable_class_uid()`'s satisfiability probe forces every non-candidate selection to `True` when testing whether a condition is class_uid-satisfiable — unsound for a condition like `class_x_sel or not other_sel`, where `not other_sel` is naturally `True` for the common case of an event that simply belongs to a different class. Verified empirically: such a rule gets bucketed under one specific `class_uid` and is **never even attempted** against events of any other class, despite genuinely being satisfiable there — a silent, unrecoverable missed detection for any rule combining a class-tagged selection with a negated classless one.

9. **`services/ws4-detection/main.py:110`** — `Detector._load()`/`reload()` only rewires stateful rules onto a shared window counter when `BUS_BACKEND` is `redis`/`redis-sentinel`. On the **default** in-memory backend, `load_rules()` builds fresh `Rule` objects each carrying a brand-new empty `DequeWindowCounter` — every hot-reload tick silently resets all in-flight sliding-window state to zero, contradicting `reload()`'s own docstring claim that unchanged rules keep their window across a reload. A brute-force detector at 4-of-5 events can be reset to 0 by an unrelated rule-file touch, missing the real 5th event.

10. **`services/ws4-detection/tenants.py:79`** — `load_disabled_rules()`'s module-level cache has no TTL/mtime check and is never invalidated by the hot-reload watcher (which only globs `RULES_DIR`/`ALLOWLISTS_DIR`, never `TENANTS_DIR`). An operator re-enabling a disabled rule mid-incident by editing the tenant YAML gets no effect until the whole process restarts, with nothing logged to indicate the change didn't apply.

11. **`services/ws7-dashboard/templates/default.conf.template:33`** `[manual]` — The `/api/alerts` nginx location proxies straight to OpenSearch with **no `X-Api-Key` forwarding and no auth check of any kind**, unlike the three sibling proxied routes (`/api/auth/`, `/api/triage/`, `/api/rules`), which all forward `X-Api-Key`. This means even in a deployment with `FENGARDE_API_KEY` **set** — i.e., auth deliberately turned on — the dashboard's own alert-feed endpoint stays completely open. The client-side login gate in `index.html` protects nothing at the data layer.

12. **`SSOT.md:78`** `[manual, doc discrepancy]` — Claims bus-only coupling between services is "**Proven** — grepped, zero hits, confirmed twice." Directly contradicted by `services/shared/users.py:34-37`, which puts `services/ws6-inventory` on `sys.path` and imports `mfa` from it — a real, working cross-service import (defensively wrapped in `try/except`, but present and live in `_TOTP_AVAILABLE`). This is the exact rule `CLAUDE.md:44` states as a hard architectural invariant ("no service imports or calls another").

### MEDIUM

13. **`contracts/rules/dc_mass_vm_delete.yml:10`** `[manual]` — The rule's selection (`class_uid: 6003, activity_id: 4`) has no `siem.source_type` scoping to `vmware_vsphere`. `services/ws2-normalization/parsers/k8s_audit.py` can also emit `class_uid: 6003, activity_id: 4` (its `delete` verb mapping), and `base.py:resolve_sector()` lets `meta.sector` override any parser's default sector as long as it's a recognized value — so a Kubernetes deployment tagged `sector: datacenter` can trip "Mass VM deletion via hypervisor API (ransomware/sabotage pattern)" on 5+ pod/deployment deletions, not VM deletions. Not a missed detection — an over-broad, mislabeled one.

14. **`infra/docker-compose.yml:200`** `[manual]` — `devkit-feeder` has no `profiles:` gate (unlike `prometheus`/`grafana`, which are `profiles: [observability]`), so it unconditionally injects a synthetic SSH brute-force burst into `raw.events` on every plain `docker compose up`. This is a well-commented, intentional demo feature ("a fresh `docker compose up` yields a REAL alert with no manual step") — but an operator who copies this compose file as a production starting point gets a fabricated alert with no explicit opt-in, discoverable only by reading the inline comment.

## 6. Genuinely investigated and refuted (1)

**`services/shared/bus.py:587`** — Raw claim: `Bus()` constructs a fresh, uncached `_MemoryBus()` on every call, and `serve()`'s per-topic worker threads each call `bus_factory()` independently, so workers on the default memory backend never share state and messages are silently lost. All 3 lenses confirmed the underlying code fact (true: no caching/singleton) but refuted the failure scenario: no real service `main.py` calls `serve()` relying on the default factory to share state across topics, and `runner.py`'s own docstring states this is intentional design ("each worker gets its own Bus instance — Redis consumer-name isolation, thread-safety"). On `BUS_BACKEND=redis` the "fresh instance" is a new client object pointed at the same shared Redis server, which is exactly how a stateless client is supposed to work. Correctly refuted.

## 9. Fix session (2026-08-13, same day) — what got fixed, what didn't

After this report's first version, all 33 unverified §5 findings were independently re-verified by direct code reading (no more agent/workflow spend — the account was still at its cap, so this was done manually, one file at a time, following the same `engineering:code-review` skill dimensions: security / performance / correctness / maintainability). **32 of 33 confirmed as real; 1 (`tools/coverage_gate.py:33`, TARGETS drift) stayed inconclusive** — I couldn't establish it cleanly and declined to touch the coverage gate on a guess. Combined with the original 14 confirmed findings, that gave 46 real, actionable items. All of them were fixed except three deliberate exceptions, explained below.

### What was fixed

**Correctness/crash bugs (all reproduced-then-verified-fixed):**
- `timeutil.py:43` / `base.py:104` — both Infinity/NaN crashes now return `None`/`default` instead of raising (`math.isfinite` guard).
- `parsers/__init__.py:172` — `%ASA` routing now requires the real `%ASA-\d-\d+:` tag and checks `sshd[` first.
- `parsers/__init__.py:94` — mcp_agent routing now recognizes `tool_name`/`name` and `params`, matching what `McpAgentParser.parse()` itself already accepts.
- `router.py:36` — `_date_suffix()` now normalizes `OSError`/`OverflowError`/`TypeError` to `ValueError`, matching what every caller already catches, so one poison timestamp can't abort a whole batch drain.
- `storage/memory.py:62` — every read path (`find_alert`, `list_alerts`, `list_events`, `count`, `get`, `all_docs`, `indices`) now holds the same lock `index()`/`index_cas()` use.
- `engine.py:475` — `_bucketable_class_uid()`'s satisfiability probe now tries both all-other-selections-True AND all-other-selections-False before concluding a class_uid bucket is safe; reproduced the exact `class_x_sel or not other_sel` failure case, confirmed it now buckets to catch-all (`None`) instead of silently narrowing.
- `main.py:110` (ws4) — the Detector now owns a persistent `DequeWindowCounter` from construction (not `None` until Redis wires one), so `reload()` on the default in-memory backend no longer resets in-flight window state. Reproduced live: 9 sub-threshold events survive a `reload()`, the 10th still fires.
- `tenants.py:79` — added `invalidate_cache()`; the hot-reload watcher now also polls `TENANTS_DIR`'s mtime and clears the tenant-disabled-rules cache on change.

**Security hardening:**
- `syslog_udp_server.py:322` — empty/CRLF-only datagrams now consume a rate-limit token and count as dropped instead of bypassing both invisibly.
- `syslog_udp_server.py:339` — added a nested per-source-IP token bucket alongside the existing tenant-level one, so one flooding host can no longer exhaust a shared single-tenant budget and starve a real concurrent attacker's events.
